# Spec: the menu as a card-sized layer

## Design

All the changes are in `Menu.qml`, a new pure function in `Model.js`, and
the docs. Line numbers are on `fix/46-review-findings` (PR #47), which this
builds on.

Revised after Codex and agy reviewed the first draft. Three things changed:
- the keyboard focus model;
- the fallback is now a clean alternative, not an addition;
- the geometry function's inputs.

**1. Pick one screen, and use it everywhere.**

- Add `readonly property var screenFor`:
  - `root.targetScreen` when set;
  - otherwise `Quickshell.screens[0]` when `Quickshell.screens.length > 0`.
    It is a sequence wrapper, so this checks `length` (AGENTS.md);
  - otherwise `null`.
- `panel.screen` is bound to `screenFor` (`:92`), so the size and the
  monitor always come from the same screen.

**2. Geometry is pure and tested.**

- New `Model.menuGeometry(screenW, screenH, minW, maxW, viewNaturalH, insetX,
  insetY, gaps)` returns `{ width, height, top }`:
  - the view width is `cardWidth(screenW, 0.55, minW, maxW)`, as `:30`
    does today;
  - the card width is that plus `insetX`, capped at `screenW * 0.9`;
  - the card height is `viewNaturalH + insetY`, capped at `screenH * 0.85`;
  - `top` is `max(gaps, round((screenH - height) / 3))`.
- When `screenW` or `screenH` is 0 (no screen), it returns the floor width
  `minW + insetX`, the natural height and `top = gaps`. It never returns 0.
- QML passes in what `Model.js` cannot compute: `Style.space(560)`,
  `Style.space(1100)`, the card's content insets and `Style.gapsOut`.
- Node tests cover a normal screen, a screen small enough to hit both caps,
  and a null screen.

**3. The layer is the card.**

- **Size and placement.**
  - The `PanelWindow` is anchored at the top only, so layer-shell centres
    it horizontally.
  - `implicitWidth` and `implicitHeight` come from `menuGeometry`, and
    `margins.top` is `top`.
  - `card` fills it (`anchors.fill: parent`).
- **Removed:**
  - the scrim `Rectangle` (`:103-106`);
  - the full-screen `MouseArea` (`:109-112`);
  - the card's click-swallowing `MouseArea` (`:128`).
- **Kept:** `WlrLayer.Overlay`, `ExclusionMode.Ignore`, the namespace, and
  `visible: root.opened`.
- **Keyboard focus follows the shell's own keyboard panel**
  (`Ui/KeyboardPanel.qml:150-160`):
  - while open, it is `Exclusive` for a short prime, then `OnDemand`;
  - when closed, it is `None`.
  - The shell's comment explains why: "Exclusive … makes Hyprland route
    *every* pointer event to the exclusive surface … which leaves clicks on
    any other monitor unable to reach the dismissal surfaces."
  - A `focusPrimed` flag and a short timer, started on
    `onBackingWindowVisibleChanged`, mirror `KeyboardPanel`.

**4. A click outside closes it.**

- `HyprlandFocusGrab { active: root.opened && panel.backingWindowVisible &&
  root.focusPrimed; windows: [panel]; onCleared: root.close() }`.
- It is the shell's `Ui/PopupCard.qml:87-94` pattern. It is armed only once
  the window is mapped and the focus prime is done, so it cannot clear while
  the menu opens.
- While the grab is active, input goes only to the menu. A click elsewhere
  clears the grab and closes the menu.

**5. The fallback, a clean alternative.**

- If live verification shows steps 3–4 failing, the code becomes instead
  today's single full-screen `PanelWindow`, with the scrim `Rectangle`
  removed and nothing else changed. Failing means the menu closes by itself,
  keys go elsewhere, or an outside click reaches the app.
- In the fallback there is no grab and no second window. It is not dimmed,
  and an outside click still only closes the menu.
- This is the fallback the owner approved for intent question 1. The plan
  records which path shipped.

**6. Documentation.**

- **README** and **`docs/usage.md`:** the menu without the dimming.
- **AGENTS.md:**
  - `:15` and `:45` ("full-screen keyboard menu");
  - the "Verifying live" note on `hyprctl layers -j`.
- **`MicrovmView.qml`:** the comments at `:11` and `:71`.
- **`docs/capture.sh`:** if it sizes a crop from the full-screen layer.
- Captures are retaken at the next capture pass, as the owner decided.

## Alternatives rejected

- **Exclusive keyboard focus kept throughout, with a focus grab.** The shell
  documents that Exclusive routes every pointer event to the surface, so the
  outside click never clears the grab (Codex, agy).
- **A second full-screen `WlrLayer.Top` window as the fallback.** It does
  not fix a grab that clears itself on open. Under an Exclusive Overlay it
  receives no clicks either.
- **Esc-only dismissal.** The intent rules it out.
- **A dimming setting.** The intent rules it out.

## Risks

- **The focus prime and grab timing.** If the prime is too short, keys may
  not reach the menu; if too long, the grab arms late. Mirror
  `KeyboardPanel`'s timer value and verify live.
- **Keep-loaded:** the grab is bound to `root.opened`, so a closed menu
  never steals input.
- **Multi-monitor:** check it on DP-1 and DP-3.
- **Host:** only the plugin folder changes.

## Verification

- `node tests/run.js` passes with the `menuGeometry` tests.
- `nix flake check`, the same with `--all-systems --no-build`, `nix build`
  and a fresh-clone `omarchy plugin validate` all pass.
- Live, by AGENTS.md "Verifying live", with the owner's desktop free and an
  ai-mirror grant:
  1. Open the menu. `hyprctl layers -j` shows `nixarchy-microvm-menu` at card
     size.
  2. A screenshot shows the rest of the monitor undimmed.
  3. The menu stays open for 3 s, and `j`/`k` move its cursor: keys reach
     it.
  4. Click on another window outside the card. The menu closes, and that
     window neither takes focus nor reacts.
  5. Click on the other monitor: the same result.
  6. Reopen with the other monitor focused, and repeat 1–4.
  7. The bar is healthy, and there are no new plugin warnings in `qs log`.
- If 3, 4 or 5 fails, switch to the step 5 fallback, repeat 1–7, and record
  it in the plan.
