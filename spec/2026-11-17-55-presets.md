# Spec: presets, saved starting points for the create form

## Design

**Where the line numbers come from:** `feat/55-presets`, checked by opening
each one.

**Revised after codex reviewed the first draft.** agy was not obtained: exit=3,
"Our servers are experiencing high traffic right now, please try again in a
minute. (UNAVAILABLE (code 503): No capacity available for model
gemini-3.8-flash-high on the server)". Five findings were confirmed against the
code and changed here: oversized files now get a named diagnostic (section 1),
record framing is described honestly (section 1), a cold direct-to-form open is
defined (section 4), a pick cancels a pending agent call (section 5) and the
live clean-up removes the permanent test machine (Verification). The count and
total-size finding was already disclosed in Open points and is stated more
plainly there.

**How this was written.** Two proposals were merged: a minimal one and a
risk-first one. Where they differ, the smaller one won unless the other showed
a concrete failure. Those picks are marked "(risk)".

**Summary.** A preset is a `*.json` file in
`$XDG_CONFIG_HOME/nixarchy/microvm/presets/`. One `find` reads the folder.
One strict parser in `Model.js` turns the output into at most 9 presets and a
list of per-file errors. The create form gets a top row, "Start from a
preset", where `1` to `9` pick a preset. The empty state lists the same
presets with the same digits. Applying a preset reuses `applyAgentReply` on a
blank `emptyForm`, then `validateForm`, then the review screen. No new file,
no new setting, no new flake check, no new QML component.

### 1. Reading the folder

- **Argv**, from a new `Model.presetsArgv(configHome)`. It returns `null` when
  `configHome` is empty, like `pkgScriptPath` (`Model.js:1284`):

  ```text
  ["timeout", "2", "find", "-L", "<cfg>/nixarchy/microvm/presets",
   "-maxdepth", "1", "-type", "f", "-name", "*.json", "!", "-name", ".*",
   "-size", "+16k", "-printf", "\\036%f\\037\\025", "-o",
   "-printf", "\\036%f\\037", "-exec", "cat", "{}", ";"]
  ```

  An oversized file prints only its record header and a one-byte marker
  (`\x15`), and is never `cat`'d. A parsed body that is exactly `\x15` is
  `too large (over 16 KiB)`.

  - It has the shape of `sshKeysArgv` (`Model.js:1948`), read the way
    `keysProcess` is (`MicrovmState.qml:803-807`): a `StdioCollector`.
  - `timeout`, `find` and `cat` run by name from `PATH`, as an array, with no
    `sh -c`. The README lists them as requirements.
- **Special files.** `-L` makes `-type f` test the target. A FIFO, socket,
  device, directory or dangling link is never `-exec`'d, so `cat` cannot block
  on it. `timeout 2` bounds a hung mount and a file swapped for a FIFO after
  the stat.
- **Symlinks** are followed, but only to a regular file. Home Manager and
  dotfile managers publish config as store links. The repository's symlink ban
  covers the repository, not the user's folder (intent, Constraints). A link to
  anything else is skipped silently.
- **Size.** `-size +16k` matches files over 16 KiB, which are named but not
  read, so the skipped-files caption can say `too large (over 16 KiB)` for
  them. The parser also rejects a body over 16384 characters, which catches a
  file that grew after the stat, with the same message.
- **Count.** The parser sorts by file name, examines the first 32 entries and
  keeps at most 9 valid presets (`MAX_PRESETS = 9`). One preset per digit means
  no list navigation and no overflow case. When files are skipped, the note
  says `9 of 14 shown`.
- **Record framing.** Records are `RS name US body` (`\x1e`, file name,
  `\x1f`, body). The sshKeys framing (`\n%f\t`) breaks on JSON bodies, which
  contain newlines. A valid JSON body cannot hold a raw 0x1e or 0x1f, but an
  invalid file can, and a file name can too. Such a file can end its own record
  early and start a forged one, so a diagnostic may name the wrong file. It
  can only mint a preset out of the user's own folder, and that preset passes
  the same per-file contract. Physical boundaries are not recoverable from
  content, so this is accepted and tested (section 9), not prevented.
  A chunk without `\x1f` is ignored.
- **Safe labels.** The label is the file name without `.json`, passed through
  `sanitize(..., 32)` (`Model.js:100`), which strips control and bidi
  characters. An empty result becomes `(unnamed)`. Labels and errors are drawn
  with `textFormat: Text.PlainText`, as the other rows are. The same label
  prefixes every error.
- **A missing or empty folder** yields no output, so no presets and no error
  (decision 6). A failed read looks the same as an empty folder.

### 2. The per-file contract: `Model.parsePreset(text)`

It returns `{ok, reply, error}`. It reuses `AGENT_FIELDS` and
`applyAgentReply` (`Model.js:1892`, `Model.js:1901`) and adds the stricter
checks the intent asked for. Nothing is added to `AGENT_FIELDS` or
`schema.json`, so *(checked: schema-fields)* still holds.

- **Not valid JSON, or not an object:** `not valid JSON` (`parseObject`,
  `Model.js:1842`, rejects arrays and `null`). The engine's own message is
  never shown, because it can quote file content, and a symlink could point at
  any file (risk).
- **Unknown key:** `unknown key "<sanitize(key, 24)>"`. This rejects
  `startNow`, `sshKey`, `describe` and `editing` with no extra code, because
  none is in `AGENT_FIELDS`. That settles decision 5 and the SSH-key
  constraint.
- **Wrong type:** run `applyAgentReply(reply, emptyForm())` and treat any
  `rejected` entry as an error, `wrong type: memory`. This reuses the
  per-field conversion, including the `kind` enum.
- **Stricter than the agent gate**, which accepts any `shares` with a numeric
  `length` and truncates long strings (`Model.js:1927-1938`):
  - `shares` must be a real array of at most 16 entries (`schema.json:20`),
    each an object with exactly `source` and `mountPoint`, both strings;
  - strings must not exceed the schema's `maxLength`: `name` 64, `template`
    32, `reasoning` 280, share parts 4096. A preset is rejected, not
    truncated, so the file the user wrote is the form they get.
  - Every error is a fixed phrase naming a key, never a value.
- **No required keys.** `{}` is a valid, blank preset.
- **`name` and `reasoning`** are type-checked, then ignored. `name` is ignored
  by decision 2. `reasoning` is dropped so the row has no second text channel.
- **Ranges and the template** (memory, cores, port, template in the live list)
  are not duplicated. `validateForm` checks them on the same path as typed
  input (`Model.js:970`). The template check runs against the live list, which
  arrives asynchronously, so a good preset can show a template error until the
  list lands, as typing does.
- **`Model.presetForm(reply)`** builds the form (decision 1):
  - start from `emptyForm(reply.kind === "permanent" ? "permanent" :
    "disposable")`, never from the current form, so the result is the same
    every time;
  - apply `applyAgentReply`, then set `name = ""` and `describe = ""`;
  - `startNow` stays true and `sshKey` stays empty;
  - set `preset` to the label, so the row shows what was applied.
- `emptyForm` gains `preset: ""`. `tests/model/form.test.js:272` requires every
  `FORM_FIELDS` key to be in `emptyForm`, and values stay strings and bools.

### 3. Where errors show

Not on `agentError`, which belongs to the agent's busy state
(`MicrovmState.qml:240`, `:584-642`), and not on `lastError`.

- `MicrovmState.presetErrors` is a list of `<label>.json: <cause>` strings.
- `Model.presetNote(count, errors)` builds one dim caption, for example
  `2 presets skipped: a.json: unknown key "x"; b.json: not valid JSON`. It
  shows at most 2 errors, then `+n more`, and clamps each to 120 characters.
- It is drawn under the preset row in the form and under the preset line in
  the empty state.
- **The row shows when presets or errors exist** (risk). A user who just
  dropped a bad file must see why it is missing, which a hidden row would
  not show.
- No folder and no files: no row, no caption, and the plugin looks as it does
  today.

### 4. When presets are read (no timer)

- `MicrovmState.readPresets()` starts `presetsProcess`, guarded by `if
  (presetsProcess.running) return`. It runs from exactly two places:
  - `onActiveChanged` when `active` becomes true. `active` is `views > 0`
    (`MicrovmState.qml:44`, `:287-290`), so this is the first surface to open,
    not every open: a second surface opened while one is still open does not
    read, and uses what the first read left in `MicrovmState.presets`;
  - the `u` key, beside `MicrovmState.refresh()` (`MicrovmView.qml:357`).
- It is not in `probe()` or `refresh()`. Both run on the bar's timer while a
  bar exists (`MicrovmState.qml:162`, `:255`, `:272`), so tying presets to
  them would read the disk with both surfaces closed (intent, Constraints).
- It is not called from `openForm`: a late result would insert the row and
  shift the field indexes under the user.
- No `FileView` watch, which would be a standing watch with the surface
  closed.
- **A cold open sees no presets.** `start()` runs synchronously on open, and
  the read begins on the same open. A direct-to-form open
  (`'{"create":true}'`) on a closed plugin therefore snapshots an empty list,
  and the row shows from the next form open. This is accepted: the read takes
  milliseconds, and a late row would shift the field indexes. The docs say it,
  and live step 2 opens the form twice.
- **A snapshot per form open** (risk). `CreateForm.start()`
  (`CreateForm.qml:87-93`) copies `MicrovmState.presets` and
  `presetErrors` into `root.presets` and `root.presetErrors`. A read that
  lands while the form is open changes nothing, so key 2 always means what is
  drawn. A new read shows on the next open.
- `statusJson()` (`MicrovmState.qml:~660`) gains `presetReads`, a count of
  reads started, plus `presets` and `presetErrors` counts. The no-poll rule
  can then be checked live, as `statsReads` does for #53.

### 5. The picker: exact keys

- **`FORM_FIELDS` gets one entry, first:** `{ key: "preset", widget:
  "preset", label: "Start from a preset", create: true, presets: true }`
  (`Model.js:1150`).
  - `visibleFields` (`Model.js:1167`) hides it unless `state.presets > 0` or
    `state.presetErrors > 0`, and, as for `describe`, when editing
    (`create: true`). It never shows on an edit.
- **Keys.** On the preset row only, a bare `1` to `9` picks preset N.
  `Model.presetIndex(text, count)` returns an index, or -1 for `0`, `10`, a
  letter or an N above the count. It is called from one new branch in
  `CreateForm.navKey` (`CreateForm.qml:202`), guarded by `root.current.widget
  === "preset"`.
- **Typing is unaffected.**
  - The preset row is not `takesText` (`CreateForm.qml:323`), so it has no
    `TextInput` and no digit reaches a text field through it.
  - Text fields forward only navigation keys (`CreateForm.qml:429`).
  - The digit branch runs only when the row itself has focus: by `tab`, `↑`
    or the start position.
  - Memory, cores, port and name take digits as now.
  - Alt+digit (risk's choice) is not used. It adds a second key path, fails
    on layouts where the digit row needs Shift, and may be taken by the
    compositor. The preset row being non-text already protects typing.
- **On pick**, `CreateForm.pickPreset(i)`:
  - first calls `MicrovmState.resetAgent(surface)` (`MicrovmState.qml:621`),
    so a pending reply cannot land on the picked preset
    (`MicrovmView.qml:557` applies any reply that arrives while the form is
    open), and the busy `describe` field is freed;
  - runs `setForm(Model.presetForm(preset))`, clears `reasoning`, and calls
    `begin()`;
  - moves the cursor to `name` with `fieldIndexOf(fields, "name")`;
  - sets `touched` to the keys the preset supplied, except `name`, and leaves
    `attempted` false (risk). A bad value in a preset field is red at once,
    but "A name is required" is not red before the user types. This differs
    from the agent path (`MicrovmView.qml:568`) on purpose.
  - A pick replaces everything typed so far (decision 1). The hint and the
    docs say so.
- **Submit stays separate:** `enter`, then the review screen for a permanent
  VM (`MicrovmView.qml:200-228`).
- **Display.** One wrapped caption under the row: `1 python-4g   2 web   …`,
  in the existing caption font with `Color.*` and `Style.*` tokens. No mouse
  targets; the form is keyboard-driven.
- **Hint line** (`CreateForm.qml:511-520`): `f.widget === "preset"` returns
  `1-9 pick   tab next   esc cancel`.
- **More presets than keys** cannot happen: 9 are kept, the rest are named in
  the note.
- **Cursor on open.** `c` still starts at `name` (`MicrovmView.qml:361`). The
  row sits above it, reached by `↑` or `shift+tab`. `fieldIndexOf` handles the
  shifted index, and `start()` has no hard-coded index.
- **Keys shift when files change.** Presets sort by file name, so a name
  prefix such as `10-box.json` pins a place. The docs say this.

### 6. The empty-state "start here"

- **Condition.** `Model.startHere(state)` is true exactly when `emptyText`
  reaches its last branch, "No VMs yet — press c to create one"
  (`Model.js:703-710`): loaded, reachable, not filtered, no upstream or list
  error, `showStopped` on. `emptyText` calls `startHere`, so they cannot
  disagree, and a test pins it.
- **Text.** With `state.presets > 0`, the last line becomes `No VMs yet — press
  c to create one, or start from a preset`. The line `1 python-4g   2 web   …`
  and the errors caption go below it in the same column
  (`MicrovmView.qml:716-735`). `emptyText`'s state gains `presets`, and the
  caller passes it.
- **Key.** `handleTextKey` (`MicrovmView.qml:353`) gets one branch. When
  `startHere` holds and `presetIndex(key, presets.length) >= 0`, it calls
  `openForm("disposable", "name")` and then `createForm.pickPreset(i)`. The
  digits do not exist once any VM is listed.
- **Filter box.** While the filter field has focus the key catcher is
  `blocked` (`MicrovmView.qml:407`), so digits type into the filter.
- **Gate.** `openForm` refuses until `upstreamOk`, with "checking nixarchy…"
  (`MicrovmView.qml:175-180`). Presets sit behind the same verdict with no
  extra code.
- **Menu and IPC:** unchanged (decision 7). `Menu.wantsCreate` is untouched.
  Both hosts share `MicrovmView`, so both surfaces get everything.

  - group "All VMs", keys `1-9`: "With no VMs: create from that preset".

- **`docs/usage.md`.** An "Everyday tasks" entry (`docs/usage.md:199`) and a

- **`AGENTS.md`.** One `(by hand)` rule: the presets folder is read only by

### 9. Tests: new `tests/model/presets.test.js`

`tests/run.js:5-8` loads it automatically.

- **`presetsArgv`:** shape, `null` for an empty home, trailing slash trimmed,
  no `sh`.
- **`parsePresets(raw)`** returns `{presets, errors, more}`:
  - a valid file, sorted by name, label without `.json`;
  - 10 valid files give 9 and `more`;
  - an oversize body, the `\x15` marker body, an empty body, a chunk without
    `\x1f`;
  - a bidi or control character in a name is sanitized in label and error.
- **`parsePreset` rejects:**
  - invalid JSON, an array, `null`;
  - a body holding `\x1e` and `\x1f` that forges a second record: the first
    is reported invalid, and the test pins what the forged record yields;
  - `startNow`, `sshKey`, `describe`, `editing`, `__proto__`;
  - `memory: "4096"`, `kind: "x"`;
  - `shares` as a non-array or an array-like with a numeric `length`, an
    entry with an extra key or a numeric `source`, 17 entries;
  - an over-length `template`;
  - and no error text contains a value from the input.
- **`parsePreset` accepts:** `{}`, a `name` that is then ignored, `sshPort:
  null`.
- **`presetForm`:** blank-based, never inherits earlier fields; the same preset
  twice gives the same form; `name` empty; a permanent preset with a port or
  shares sets `advanced`; `startNow` true, `sshKey` empty; a good preset
  passes `validateForm`, a bad template fails there and not in `parsePreset`.
- **`visibleFields`:** the row is first on create, absent with no presets and
  no errors, present with errors only, absent on edit; `fieldIndexOf(.., "name")`
  shifts.
- **`presetIndex`:** `"1".."9"` map to 0..8; `"0"`, `"10"`, `"a"` and an N
  above the count give -1.
- **`startHere` and `emptyText`:** true only in the last branch; false when
  filtered, on an upstream or list error, or with stopped VMs hidden; the
  hint appears only with `presets > 0`.
- **`presetNote`:** at most 2 errors then `+n more`; clamped to 120.
- **`SHORTCUTS`:** the new key labels fit 12 characters.
- Existing `form.test.js` and `keys.test.js` assertions that assume
  `describe` is first are updated in the same change.

## Alternatives rejected

| Alternative | Why not |
| --- | --- |
| Reuse `schema.json` as the file validator | It requires `kind`, `name`, `template` and `reasoning` (`schema.json:6`), which a partial preset lacks. The strict check is about 30 lines in `Model.js` and Node-testable. |
| `FileView` per file, or `Qt.labs.folderlistmodel` | No size cap, no symlink or FIFO policy. `find -L -type f -size` gives all three. |
| A streaming `SplitParser` reader with a count and byte budget that fails closed over 32 files (risk) | More QML and a `signal(15)` path for a user's own folder. The 2 s `timeout`, the 16 KiB per-file cap and the parser's 32-entry window bound the work. See Open points. |
| A depth scan before `JSON.parse` (risk) | A file is at most 16 KiB, so nesting is at most that deep. No concrete failure shown. Checked live instead. |
| Alt+digit in the form (risk) | See section 5: a second key path with layout and compositor risk, for a protection the non-text row already gives. |
| Name allowlist regex in `find` (risk) | `sanitize` plus `RS`/`US` framing already makes any name safe to print and parse. |
| Refusing to load permanent-only keys in a disposable preset (risk) | The values stay hidden on a disposable form and show if the user flips the kind. Not a failure. |
| Duplicate-label rejection (risk) | File names in one folder are unique. Only a forged record could repeat one, and that mints nothing new. |
| A list picker with `↓`, `enter` and more than 9 presets | New navigation state and a height problem on the menu card. One digit each and a cap of 9 remove the overflow case. |
| Bare digits as global form keys | They would swallow typing in name, memory, cores and port. They work only on the non-text row. |
| A step before the form, or a new list key | A step adds a mode and a keypress to every create. A list key competes with `i`, `c` and the filter. |
| A `label` key in the file | It would need an `AGENT_FIELDS` and `schema.json` change, which breaks *(checked: schema-fields)*. The file name is the label (decision 3). |
| Merging the preset over the current form | Not repeatable (decision 1). |
| Re-reading in `openForm` | A late result shifts the rows. Reading on open and on `u` is early enough. |
| An off switch | Decision 6. |
| Errors on `agentError` or `lastError` | `agentError` is the agent's busy state and is cleared on reset. `lastError` is the footer for failed commands. |

## Risks

- **Preset row inserted late.** The snapshot in `start()` prevents a shift
  mid-form. A read that lands after the form opened shows on the next open.
- **Form height.** One row plus up to 3 caption lines. The form already scrolls
  (`CreateForm.qml:301`), and the card derives from the screen. Checked live on
  both surfaces.
- **GNU `find`.** `-printf` and `-size +16k` are findutils, which `sshKeysArgv`
  already assumes (`Model.js:1950`). `timeout` is a new command, so it is a
  documented requirement. A missing one fails silently as "no presets".
- **Bounded by time, not by file count.** `find` reports every file in the
  time allowed. See Open points.
- **A forged record boundary** can only fake a preset from the user's own
  folder.
- **Deep JSON in Quickshell's engine.** Node cannot test its limits. A 15 KiB
  `[[[[…` file is a live step.
- **A `shares` entry naming a sensitive host path** is not blocked at the file.
  It reaches `validateForm` and the review (intent: the review stays the
  backstop). Disposable creates have no review and offer no shares.
- **`FORM_FIELDS` and `emptyForm` changes** can break assertions that assume
  `describe` is first, or exact key sets (`form.test.js:267`, `:272`). They are
  updated in the same change.
- **`emptyText` gains a `presets` input.** A caller that does not pass it
  never shows the hint. A test covers the call in `MicrovmView.qml`.
- **Bare digits on the list** act only when no VM exists and the filter is not
  focused. A mistyped digit opens a form, which `esc` closes without creating.

## Open points

- **"Bounded in count and total size" (intent, Constraints).** This design
  bounds each file (16 KiB), the work (2 s) and what is kept (32 examined, 9
  shown). It does not cap how many files `find` reports. A strict count cap
  needs the streaming reader rejected above. Until then `StdioCollector`
  holds all of `find`'s output in memory: at most 16 KiB per file for every
  file in the folder, within 2 s. A file that grows after the stat is cut by
  `timeout`, not by a byte count. **Decided by the owner on 2026-11-17, with
  the approval:** the time bound is enough for a folder the user owns. No
  streaming reader.
- **Digits and `event.text` under the layer-shell panel** were not checked.
  Live step 9 covers it.
