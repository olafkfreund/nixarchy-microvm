# Spec: the small places where the code does not mean what it says

## Design

### 1. The lost last line does not exist. Item 1 is retracted.

This was the one item with a user at the end of it, so it was checked first, and
it does not survive the check. Quickshell flushes the parser buffer on exit,
before `exited`:

```cpp
// quickshell src/io/process.cpp:274-282, Process::onFinished
if (this->mStdoutParser) this->mStdoutParser->streamEnded(this->stdoutBuffer);
if (this->mStderrParser) this->mStderrParser->streamEnded(this->stderrBuffer);
...
emit this->exited(exitCode, exitStatus);
```

and `SplitParser::streamEnded` (`src/io/datastream.cpp:97-99`) is exactly the
missing flush: `if (!buffer.isEmpty()) emit this->read(QString(buffer))`. So a
child that dies mid-line delivers that fragment through `onRead` — that is,
through `appendLog` (`MicrovmState.qml:663-664`) — and only then does `onExited`
(`:667`) append the `── exit` marker. The order is right, not wrong.

This is the code we run: `nixpkgs#quickshell` is 0.3.1 built from
`refs/tags/v0.3.1`, the tag read above. The one path that does not flush is
`onErrorOccurred` on `FailedToStart` (`src/io/process.cpp:289`), which drops the
process without `streamEnded` or `exited` — but a binary that never started
wrote nothing, and the hold it leaves is what `escapeTimer`
(`MicrovmState.qml:305-310`) already exists for.

The outcome is a one-line comment at `MicrovmState.qml:663` recording that the
parser flushes the tail before `exited` and the marker is therefore last, so the
next reader does not re-derive it. Nothing else changes; the item closes on the
issue as not-a-defect with the two citations. That retraction is the point of
the exercise — #39 exists because descriptions drift from code, and this one
had.

### 2. `counts.stopped` is removed, not fixed.

`Model.js:632-642`. The defect is the bare `else out.stopped++` — no whitelist,
so the field means "not running" while its name says "stopped". Today the
parsers emit only `running`/`stopped` (`:367`), `failed` (`:404`) and `none`
(`:349,461`), so a failed VM lands in both `stopped` and `failing`, and a
never-built machine reads as stopped.

The field is removed. Every reader is a named field access and none names it:
`summaryText` (`:644-649`) and `footerText` (`:651-654`) take
`total`/`running`/`pending`; `Model.listActions` (`:1385-1391`, via
`MicrovmView.qml:89`) takes `pending`; `MicrovmView.qml:388,392` take `running`
and `failing`; `Panel.qml:84-88` takes `total`, `running` and `failing`.
`statusJson` (`MicrovmState.qml:449-465`) does not serialise `counts`, so
nothing sees the object's shape but the deep-equal at
`tests/model/rows.test.js:137`.

A field that is wrong and unread is a trap for the next caller; right and unread
it is still code nobody asked for. When a footer wants it, it arrives with a
whitelist and a test in the PR that needs it.

### 3. `known()` is deleted, comment and all.

`MicrovmState.qml:213-220`. Its comment describes a guard applied nowhere. The
IPC target it appears to protect (`Panel.qml:15,76-84`) exposes `open`, `close`,
`show`, `hide`, `toggle`, `refresh`, `create` and `status` — none takes a VM
name, so there is no name to guard. Wiring it up means inventing a name-taking
verb, a feature with its own intent. The guard is six lines; it belongs beside
its first caller, in the PR that adds one.

### 4. `parseJsonLines` and `streamKey` are deleted.

`Model.js:175-186` is called only from `tests/model/parsing.test.js:71-74`; the
live `list --json` path is `isJsonList` + `parseJsonArray` beside it. The test
goes in the same commit — a suite certifying unreachable code is worse than no
test, because it reads as evidence. `streamKey` (`MicrovmState.qml:151`) is
written by `startStream` (`:291`) and read nowhere; the property, the `key`
parameter and the argument at the one call site (`:260`) all go.

### 5. `appendLog` batches; the cap moves to `Model.js`.

`MicrovmState.qml:298-303` copies the capped array, pushes, trims to 400 and
reassigns, per line — and `LogView.qml:109` binds `model: root.lines`, so each
reassignment rebuilds every delegate. A `nix build` pays both several hundred
times.

Lines accumulate in a plain JS array and flush to `root.log` on `Qt.callLater`,
so a burst costs one copy and one rebuild instead of N. The assignment mechanism
is unchanged, so the notification driving `LogView` and `onLinesChanged`
(`LogView.qml:49`) behaves as it does today. The merge and cap become
`Model.capLog(existing, incoming)` — logic in `Model.js`, testable under Node.
`onExited` (`:667-673`) flushes any pending batch before appending the `── exit`
marker, so the marker stays last, after the tail line §1 puts just before it.

### 6. `Panel.qml` pushes `hideWhenEmpty` changes.

`pushSettings()` (`Panel.qml:26-33`) includes the key; `:35-37` has handlers for
the other three. Add `onHideWhenEmptyChanged: pushSettings()`, and the pushed
copy stops diverging from the bar's.

### 7. `ask()` re-entrancy stays on the issue, out of this task.

`MicrovmView.qml:240-249` has no `if (root.confirmOpen) return`. Whether a
second question can reach it while `ConfirmDialog` is up needs a running shell —
the same blocker as #34. Everything else here is settled from a checkout;
carrying this one holds the whole PR on desktop availability for the smallest
item on the list. It stays open on #39, noted as deliberately left, so it is
recorded rather than rediscovered a third time.

## Alternatives rejected

**Wire `known()` up instead of deleting it.** Rejected: there is no caller to
wire it to. An IPC verb taking a name — `start <name>`, say — changes the
surface's contract and needs its own intent; smuggling it into a cleanup PR is
how a cleanup stops being reviewable against its plan.

**Fix `counts.stopped` with a whitelist** — `if (r.runtime === "stopped")
out.stopped++`, with `none` counted nowhere or as a new `unbuilt`. Rejected: it
keeps a field no surface asks for, and the right shape depends on what the
surface that finally wants it needs — whether `none` is its own count, whether
`pending` overlaps. Guessing now means deleting it a second time.

**Rebuild the log on a `ListModel`** — the real cure for the delegate rebuild.
Rejected for now: it changes `log`'s type, `LogView.qml`'s model and the follow
logic at `:38,49`, and is only observable on a live shell. If batching leaves
visible jank on a `nix build`, that is the upgrade path.

**Mutate `root.log` in place and call `logChanged()`.** Cheapest, and rejected:
a `var` array reassigned to the same reference may not re-drive
`QQmlDelegateModel`, and the failure mode is a log that silently stops updating.

## Risks

- **Deleting `parseJsonLines` removes a passing test.** That is the intent: the
  test certified nothing reachable. Nothing replaces it, because nothing
  replaces the function. If the upstream `list --json` work (`docs/upstream.md`)
  ever wants line-delimited JSON, it arrives with its caller.
- **Changing `counts`'s shape.** Safe reader by reader (§2): each names a field,
  none names `stopped`, and `counts` is serialised nowhere. The one break is the
  deep-equal at `rows.test.js:137`, amended in the same commit.
- **The batched log could reorder or drop the exit marker.** `onExited` flushes
  first, so the marker is appended to a drained buffer. The specific case to
  check is a process that exits in the same frame as its last output: the tail
  line arrives through `streamEnded` before `exited` (§1), so the flush in
  `onExited` sees it and the marker lands after it.
- **`Qt.callLater` after the surface closes.** A flush can fire with no view up;
  it only assigns `root.log`, which the surfaces keep across closes ("the
  surfaces are keep-loaded", AGENTS.md), so there is nothing to guard.
- **§1 rests on reading quickshell's source, not running it.** The version is
  pinned and cited, but a bump could change it; the comment names what it
  depends on, and the live check below confirms it once.
