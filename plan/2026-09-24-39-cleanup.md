6. **`Model.capLog` + batched `appendLog`.** In `Model.js`, beside `capLine`:

   ```
   // The log's whole growth rule in one place: cap each line, append, keep the
   // last LOG_CAP. `existing` arrives as a Qt sequence wrapper, so it is walked
   // by index -- never concat, never Array.isArray (AGENTS.md).
   var LOG_CAP = 400
   function capLog(existing, incoming) { ... }
   ```

   `capLog(existing, incoming)` returns a **new plain JS array**: every element
   of `existing` in order, then `capLine(stripAnsi(x))` for every element of
   `incoming`, sliced to the last `LOG_CAP` entries if longer. Both arguments
   are read by `length` and index, and a null or undefined argument reads as
   empty. It is pure: it never touches `root.log`.

   In `MicrovmState.qml`, `appendLog(line)` becomes: push the raw line onto a
   plain JS array `pendingLines` (a `property var` initialised `[]`), and
   `Qt.callLater(root.flushLog)`. `flushLog()` returns immediately when
   `pendingLines.length === 0`; otherwise `root.log = Model.capLog(root.log,
   pendingLines)` and `pendingLines = []`. `capLine`/`stripAnsi` move out of
   `appendLog` into `capLog`, so the raw line is what gets buffered.
   `startStream` (`:291`) resets `pendingLines = []` alongside `root.log`.

   `onExited` (`:669`) becomes `root.appendLog("── exit " + …);
   root.flushLog()` — one added call. **Why the marker cannot be reordered or
   lost:** `Qt.callLater` defers to after the current script execution and event
   processing, so no deferred flush can run *between* two synchronous emissions
   from the same C++ call. `Process::onFinished` is one such call: `streamEnded`
   (hence `onRead`, hence `appendLog`, hence only a *scheduled* flush) and
   `emit exited` both happen inside it. So when `onExited` runs, the tail line
   is still sitting in `pendingLines` and no flush has fired. `appendLog`
   pushes the marker behind it, and the direct `flushLog()` drains both in
   order. The `Qt.callLater` that was scheduled still fires afterwards and
   finds `pendingLines` empty, which is the early return.

   Add one `test("capLog merges, caps each line and keeps the last 400")` block
   to `tests/model/rows.test.js`. → verify by `node tests/run.js` reporting 93
   passed.

## Rollback

Each step is one commit and reverts alone: `git revert <sha>`. Steps 2 and 6
each touch code and its test together, so a revert leaves the suite green.
Step 6 is the only one with runtime risk; reverting it restores the per-line
copy at `MicrovmState.qml:298-303` and leaves `Model.capLog` unreferenced, so
revert the whole commit rather than the QML half.

Deletions are the hard ones to review: the diff shows what left, not what it was
worth. A reviewer should check, per deleted thing, that nothing points at it any
more — `grep -rn 'known\|parseJsonLines\|streamKey' .` and `grep -rn '\.stopped' .`
must each return nothing outside `intent/`, `spec/` and `plan/`. Steps 2-7 are
independent, so a deletion judged wrong reverts on its own.
