# Intent: presets, saved starting points for the create form

Closes #55. Roadmap P2, from the plan "review findings and roadmap".

- **Builds on #49 and #53.** It uses the create form, the review screen and the
  empty state.
- **Revised after Codex reviewed the first draft.** Codex's findings were
  checked against the code. They covered:
  - a file contract stricter than the agent gate;
  - bounds on disk input;
  - no read on the background refresh;
  - digit keys that must not break typing;
  - questions that were design or already answered.

  agy's review was not obtained: it returned "UNAVAILABLE (code 503): No
  capacity available".
- **Line numbers** are on `feat/55-presets`.

## Problem

Every create starts from the same blank defaults. There is no way to say "my
usual VM" without typing it again or asking the agent.

- **The defaults are fixed.** `Model.emptyForm` gives template `shell`, 1024 MiB,
  1 core, with start-at-boot and start-now on and nothing else (`Model.js:932-940`). A user who always wants a 4 GiB,
  2-core permanent VM with a share retypes it each time.
- **The only shortcut is the agent.** `i` opens the form at Describe, runs
  `claude` once, and fills the form from the reply (`MicrovmView.qml:557`,
  `Model.js:1901`).
  - It needs the agent, a network call and a wait, for a result the user
    already knows.
  - The answer can differ from one run to the next.
- **Templates do not cover it.** `nixarchy vm templates` only picks the guest
  image (`Model.js:1296`). It sets no memory, cores, port, share or kind.
- **The empty state gives no start.** With no VMs the list says "press c to
  create one" (`Model.js:703`). A new user sees a blank form, not a choice.

## Proposed outcome

- **Presets are files the user owns.** JSON files under
  `$XDG_CONFIG_HOME/nixarchy/microvm/presets/*.json`, with the same keys as
  `AGENT_FIELDS` (`Model.js:1892`). The plugin only reads them.
- **A preset is trusted exactly as much as an agent reply.**
  - It goes through `Model.applyAgentReply`, then `validateForm`, then the
    review screen, as a reply does.
  - Nothing in a preset is executed. The user sees the filled form and
    confirms.
  - Equal trust is not equal checking. `applyAgentReply` silently skips unknown
    keys and accepts any `shares` value with a numeric `length`
    (`Model.js:1908`, `Model.js:1927`), and `schema.json` requires `kind`,
    `name`, `template` and `reasoning` (`schema.json:6`), which a partial
    starting point does not carry. The file contract therefore needs its own
    statement: which keys are required (none is the intent's aim), that an
    unknown key, a wrong type or a malformed `shares` entry is rejected by file
    and key, and that a rejected file is not applied. Whether the spec reuses
    `schema.json` or adds a stricter check is a spec decision; the allowed
    fields stay equal to `AGENT_FIELDS`.
- **In the create form,** presets appear as one-key choices. They are choices
  for creating only; the same form edits existing VMs.
- **In the empty state,** they appear as "start here".
- **Repeatable and offline.** A preset needs no agent, no network and no wait.
- **A bad file is told, not lost.** A file that is not valid JSON, or has a
  wrong-typed or unknown key, tells the user which file and what, instead of
  silently dropping it.
- **Words match behaviour:** the README key tables, `docs/usage.md`, the
  shortcut sheet and the Safety section describe presets.

## Affected users and systems

- **Who sees a change:** anyone who drops a file in the presets folder. With no
  folder or no files, the plugin looks as it does today.
- **Code:**
  - `Model.js`: the parser, the listing argv and tests;
  - `MicrovmState.qml`: reading the folder;
  - `MicrovmView.qml`, `CreateForm.qml`, and the list's empty state;
  - possibly `Menu.qml` and `Panel.qml`, if a preset can be named on open.
- **Package and docs:** `flake.nix`'s `files` list for any new runtime file,
  `README.md`, `docs/usage.md`.
- **Later:** template packs (P1, upstream) may ship presets. Row actions (P3)
  are out of scope.

## Constraints

- **AGENTS.md rules that hold:**
  - argv arrays only, run by name from `PATH`;
  - logic in `Model.js` with a Node test;
  - no hardcoded colours;
  - a new runtime file goes in the `files` list.
- **The plugin writes nothing.** Presets are read-only to it. The user edits
  the files.
- **Nothing polls while every surface is closed.** Presets are read on an
  explicit open or refresh event, not on a timer. The existing probe is not that
  event: `refresh()` calls `probe()` and runs on a timer while a bar exists
  (`MicrovmState.qml:255`, `MicrovmState.qml:272`), so tying presets to it would
  read the disk with both surfaces closed.
- **Disk input is untrusted and bounded.**
  - Discovery and reads are bounded in count and total size and never block on
    a special file such as a FIFO.
  - The policy for symlinks and non-regular files is stated. The repository's
    symlink ban (`AGENTS.md`) covers the repository, not the user's folder.
  - File names become labels and diagnostics, so they are shown safely.
  - Mechanisms and numeric limits are for the spec.
- **Choosing a preset never breaks typing.** The form takes digits in names,
  memory, cores and ports, and text fields pass keys to the shared handler
  (`Model.js:1153`, `CreateForm.qml:429`). Picking a preset must not swallow
  ordinary text entry, and submitting stays a separate action.
- **Same upstream gate.** Presets sit behind the "checking nixarchy…" verdict,
  and a preset's `template` is checked against the live templates list
  (`Model.js:778`), which arrives asynchronously.
- **The agent contract stays.** `schema.json` and `AGENT_FIELDS` must name the
  same fields *(checked: schema-fields)*. A preset-only key would break that.
- **A preset cannot carry an SSH key.** `sshKey` is outside `AGENT_FIELDS` on
  purpose: it is login access to the guest.
- **Disposable creates have no review screen.** The form is the only
  confirmation there (`MicrovmView.qml:200-228`).
- **The review stays the backstop** for a permanent VM, including for a
  `shares` entry naming a sensitive host path.
- **Out of scope:** row actions (P3), shipping presets in a template pack (P1),
  and the plugin writing or saving presets.

## Decisions

The owner approved the recommendations on 2026-11-17:

1. **A preset starts from a blank `emptyForm(kind)`,** so it gives the same
   result every time.
2. **A preset's `name` is ignored,** and the cursor is put on the name field.
3. **The label is the file name.** No new key, so `schema.json` and
   `AGENT_FIELDS` stay equal.
4. **The picker is a top row in the form,** keyed so that typing is
   unaffected. The exact keys, and what happens with more presets than keys,
   are for the spec.
5. **A preset cannot set `startNow`.**
6. **No off switch.** No folder means no presets.
7. **No named preset from the menu row or IPC** in this issue.

## Open questions

1. **What does a preset start from?** `applyAgentReply` overlays on whatever
   the form holds, so an omitted field keeps an earlier value.
   - Options: the blank `emptyForm(kind)`; or the current form.
   - Recommendation: a blank `emptyForm`, so a preset gives the same result
     every time.
2. **Does a preset carry `name`?** `validateForm` rejects an existing name, so
   a preset used twice fails the second time with "already exists".
   - Options: allow it and accept the error; or ignore `name` and leave the
     cursor on it.
   - Recommendation: ignore `name` and put the cursor there, so the user always
     types a fresh one.
3. **Where does a preset's display label come from?** The form has no slot for
   one, and `reasoning` is the agent's free text.
   - Options: the file name; or an optional `label` key.
   - Recommendation: the file name, with no new key, so `schema.json` and
     `AGENT_FIELDS` stay equal.
4. **Where does the picker live?** The issue says one-key choices in the form.
   - Options: a row at the top of the form, like Describe; a step before the
     form when `c` is pressed; a new list key.
   - Recommendation: a top row in the form, keyed so that typing is unaffected
     (see Constraints). More presets than keys, and the exact keys, are for the
     spec.
5. **Can a preset set `startNow`?** It is outside `AGENT_FIELDS` (`sshKey` is
   already excluded, see Constraints).
   - Recommendation: no. A later issue can add a separate, deliberately trusted
     field list.
6. **Is there an off switch?** A new setting would sit with `aiAssist`
   (`README.md:214-220`).
   - Recommendation: none. No folder means no presets.
7. **Should the Omarchy menu row or IPC name a preset** (`{"preset":"x"}`)?
   `Menu.wantsCreate` accepts only `create: true` (`Menu.qml:57-75`).
   - Recommendation: not in this issue.

Moved to the spec: how the folder is listed and read, and where preset errors
show (not on the agent's `agentError`, which belongs to its busy state). The
outcome that stays here is that a bad file is reported by file and cause.
